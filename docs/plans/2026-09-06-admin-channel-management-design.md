# Admin 渠道管理接入中心设计

## 目标

把 OceanDesk Admin 的“渠道管理”从占位页改为可操作的渠道接入中心。第一版复用现有平台 API，支持查看渠道能力、配置微信服务号回调凭据、轮换或停用凭据，以及查看和撤销渠道身份。Web 渠道展示本地端到端验证状态；微信客服与企业微信机器人保留清晰的待接入状态。

## 页面结构

页面由三块组成：渠道目录、渠道实例、渠道身份。渠道目录展示 Web、微信服务号、微信客服和企业微信机器人的当前能力与验证边界。渠道实例仅展示服务端返回的脱敏凭据元数据，并提供新增、轮换、停用、复制回调地址和联调说明。渠道身份只关联平台用户目录，不展示或筛选固定企业；管理员只能撤销有效身份。企业范围由 Worker 在每次消息执行时按该用户当前有效 membership 解析。

微信服务号是平台入口渠道。配置表单只填写平台内全局唯一的渠道实例 ID 和回调凭据，不选择企业，也不选择 ADP 连接。Token、AppID、AppSecret 和 EncodingAESKey 只在提交时进入请求，保存后不会从服务端取回或再次展示。

一期 ADP 应用同样是平台级单例，由服务器 `.env` 中的 `TC_SECRET_APPID`、`TC_SECRET_ID`、`TC_SECRET_KEY` 和 `APP_CONFIGS` 配置。Admin 只展示脱敏后的配置完整性和应用标识，不提供企业绑定或密钥编辑入口。

配置归属与消息授权是两层独立边界：渠道回调先使用平台渠道实例的凭据完成验签、解密和协议标准化，再根据渠道身份解析平台用户；Worker 随后从当前有效 membership 解析企业访问范围。只有身份、企业 membership 和业务权限均有效时，平台才把受控请求转发给唯一 ADP 应用；多企业且没有可信的明确企业范围时拒绝执行。创建渠道实例或绑定渠道身份本身都不会授予任何企业数据权限。

## 状态与安全边界

“已配置”仅表示加密凭据存在且启用，不表示微信真实在线。当前服务号已在本地覆盖明文与 AES/EncodingAESKey 回调边界；真实客服消息发送、多实例持久化重放保护和真实账号端到端联调仍未完成。页面必须明确显示这些限制，不能用本地测试结果冒充第三方联调。

所有管理操作继续由 `platform.manage` 服务端权限保护。凭据响应只使用固定掩码和元数据；身份撤销和凭据操作沿用服务端审计。页面提供加载、空、错误、提交中和移动端布局状态。

## 验收

- 类型检查和生产构建通过。
- Admin 可加载平台 ADP 配置状态、渠道凭据和身份数据。
- 无需企业绑定即可创建微信服务号凭据，并可轮换、停用。
- 回调地址可复制，页面明确标注明文模式和真实联调限制。
- 桌面与 390px 移动视口无横向溢出，主要操作可触达。
