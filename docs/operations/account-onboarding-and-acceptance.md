# 账号开通、验收与培训手册

本文对应 `M4-ENABLE-01`，用于销售、客服、平台管理员和试运行负责人执行企业账号开通、交付验收与基础培训。本文只描述平台已有的本地能力和受控人工流程，不替代真实 M3、ADP、微信/企微协议联调，也不包含任何真实凭据或客户数据。

## 1. 角色与安全边界

| 角色 | 负责事项 | 不应执行 |
| --- | --- | --- |
| 销售/客服 | 收集企业资料、确认联系人和 M3 客户编码、发起开通申请 | 不直接查看数据库、Token 或密码哈希 |
| 平台管理员 | 建立企业、配置 M3 映射、创建用户、分配角色和范围 | 不把平台管理员身份当作客户业务数据授权 |
| 交付/验收负责人 | 按用例验证登录、权限、隔离、查询和审计 | 不使用客户业务数据作为演示数据，除非已获得书面授权 |
| 企业联系人 | 接收一次性初始口令、首次登录并确认可见范围 | 不通过群聊、工单明文转发口令 |
| 运维人员 | 观察健康状态、任务和脱敏错误 | 不读取客户业务载荷、口令、AppKey 或 Token |

以下信息不得进入聊天记录、模型提示词、普通应用日志或截图：初始口令、平台会话 Token、M3/渠道凭据、ADP 原始载荷和未经脱敏的客户订单。

## 2. 开通前准备

开通申请应至少包含以下已确认信息：

- 企业法定/业务名称、内部企业标识和联系人手机号；
- M3 客户编码及其来源、归属企业和有效期；
- 需要开通的角色、业务工具和企业数据范围；
- 计划使用的入口：官网，或已完成真实协议准备的渠道实例；
- 交付方式、验收窗口、验收负责人和停用联系人。

管理员在录入前确认：

1. 手机号已按平台规范化，未被其他用户占用。
2. M3 客户编码在当前连接下未被其他企业占用，且来源可追溯。
3. 角色只包含业务所需的最小权限；客户员工默认不能访问平台配置 API。
4. 企业范围和字段范围已由业务负责人确认，不能用“全部数据”代替授权说明。
5. 本次开通不需要录入任意 URL、SQL、脚本或未经批准的第三方凭据。

若 M3 编码、企业归属或渠道身份无法确认，暂停开通并记录为待补资料，不通过口头承诺绕过校验。

## 3. 标准开通流程

### 3.1 建立企业和业务映射

1. 管理员在后台创建企业，填写企业名称、M3 客户编码和状态。
2. 保存后复核企业详情、M3 编码和负责人员；重复编码或无效状态必须修正后再继续。
3. 配置允许的工具、角色、企业范围和字段范围。
4. 保存配置草稿并发布，记录配置版本和操作审计事件。

平台服务端负责校验企业状态、M3 映射和权限；前端显示的企业 ID、应用 ID 或 Workspace ID 只是选择器，不能作为授权依据。

### 3.2 创建用户

1. 在该企业下创建用户并填写规范化手机号。
2. 选择已批准的角色和最小业务范围，复核用户不能访问管理功能。
3. 由平台生成一次性 6 位初始口令。口令仅在创建成功响应或受控管理员界面显示一次。
4. 通过与申请单绑定的人工渠道分别交付账号和口令；禁止在公共群、普通聊天、截图或日志中发送。
5. 在交付记录中只写“已交付/待交付”和交付时间，不记录口令本身。
6. 要求用户首次登录后立即完成密码重置；若未完成重置，不进入正式业务验收。

初始口令由服务端随机生成并以带随机盐的哈希保存，管理员不能从数据库恢复原文。连续失败会触发账号锁定和来源限流；不要通过反复尝试或手工改库解除限制。

### 3.3 首次登录与范围确认

用户首次登录后，验收负责人陪同完成：

1. 确认必须修改初始口令，并使用企业自己的强口令保管方式。
2. 查看企业名称、账号角色和允许的功能，确认与申请单一致。
3. 使用脱敏测试标识执行一次已授权查询，确认只返回本企业允许字段。
4. 验证无权功能显示明确拒绝或不可用状态，不能只依赖页面隐藏按钮。
5. 记录验收结果、trace_id、配置版本和时间，不记录业务原始载荷。

### 3.4 停用、重置和变更

- 用户离职、手机号失效或企业撤销授权时，管理员立即停用账号；停用应使旧会话、执行上下文和待发送私有结果失效。
- 用户忘记密码时只使用后台重置流程重新生成一次性口令，不通过数据库或日志查找旧口令。
- 企业 M3 编码、角色或范围变更前，先确认影响范围，再发布新配置并复核审计记录。
- 解绑渠道或收窄范围后，验证旧渠道身份、旧会话和旧上下文不能继续读取或发送私有结果。
- 账号停用、重置和范围变更均需保留申请人、审批人、执行人、时间、原因和配置版本。

## 4. 验收用例

验收记录至少包含用例编号、测试账号/企业（使用脱敏标识）、预期结果、实际结果、trace_id 或审计事件、执行人和时间。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| ACC-01 | 使用手机号和初始口令登录 | 登录成功并要求修改初始口令；口令不出现在响应、日志或聊天记录 |
| ACC-02 | 完成首次改密后重新登录 | 新口令可登录，旧初始口令失效 |
| ACC-03 | 查询本企业已授权业务标识 | 返回允许字段、查询时间和可追溯证据 |
| ACC-04 | 查询不存在或无权记录 | 对外统一提示未找到可访问记录，不泄露其他企业记录是否存在 |
| ACC-05 | 直接调用管理 API 或伪造企业/应用参数 | 服务端拒绝或忽略伪造字段，不能靠隐藏按钮通过 |
| ACC-06 | 使用两个企业账号交叉查询 | A 企业不能读取 B 企业记录；跨企业请求留下可审计拒绝事件 |
| ACC-07 | 普通客户账号访问用户、角色、渠道和配置管理 | 返回无权限；客户页面不出现可操作的管理入口 |
| ACC-08 | 连续输入错误口令 | 达到阈值后账号暂时锁定；日志只记录脱敏状态，不记录口令 |
| ACC-09 | 管理员停用用户后访问旧会话 | 登录、工具调用、执行上下文和待发送私有回复均失效 |
| ACC-10 | 重置口令并检查旧会话 | 新口令按一次性交付；旧会话按策略失效，审计记录包含原因和执行人 |
| ACC-11 | 收窄企业范围或解绑渠道 | 新请求按新范围授权，旧渠道身份/上下文不能继续读取私有数据 |
| ACC-12 | 查询上游超时、无证据或字段未知 | 返回明确错误/待重试状态，不编造订单状态、船期或费用 |
| ACC-13 | 查看操作审计和运维状态 | 可定位配置、登录、停用和失败任务；不暴露口令、Token、原始载荷或客户正文 |
| ACC-14 | 服务重启或任务租约过期 | 未完成任务可按重试边界恢复；不重复发送已确认回复，不绕过撤权 |

真实 M3、ADP、微信服务号、微信客服和企微用例必须在对应账号、协议样本和测试数据到位后单独执行。以上本地验收不能替代第三方联调记录。

## 5. 培训材料

### 客服/销售

- 先确认企业归属、M3 客户编码、联系人和授权范围，再提交开通。
- 不在聊天窗口收集或转发初始口令、Token 或客户订单。
- 账号停用、范围变更和渠道解绑应立即提交管理员处理，并说明生效时间。
- 遇到“未找到可访问记录”时，不向客户推测记录是否存在，转交授权/数据归属排查。

### 平台管理员

- 按“企业 -> M3 映射 -> 角色/工具 -> 用户 -> 范围 -> 发布”的顺序操作，每一步复核最小权限。
- 初始口令只交付一次；不能从数据库、日志或截图恢复。
- 所有重置、停用、范围变更和配置发布必须填写原因并核对审计事件。
- 不把管理员账号用于客户业务查询；需要查询时使用经过授权的客户账号和脱敏数据。

### 企业用户

- 首次登录立即修改初始口令，并妥善保管，不与同事共用。
- 只查询本人企业授权范围内的业务；发现企业名称、范围或结果异常时停止操作并联系支持。
- 不把业务查询结果、会话链接或截图转发到未授权群组。
- 看到登录失败、锁定、上游不可用或结果缺证据时，保留时间和页面提示即可，不反复尝试口令。

### 运维/交付负责人

- 使用 `/healthz`、`/readyz` 和受控运维状态入口定位服务问题，优先查看固定错误分类和任务状态。
- 不从日志复制客户正文、ADP 原始载荷、M3 Token 或渠道凭据。
- 将真实第三方联调、备份恢复和 RPO/RTO 记录放入对应发布/联调工单；不要把本地测试结果写成生产验收。

模板不得填写初始口令、平台 Token、M3/渠道密钥或未脱敏客户数据。生产交付还应关联发布工单、备份位置和变更窗口。

## 7. 当前验收边界

本手册可在本地开发环境使用脱敏测试数据验证平台账号、权限、企业范围、审计和错误状态。当前仓库尚未完成生产部署、真实备份恢复、RPO/RTO、真实 M3/ADP 或微信/企微联调；这些依赖外部账号、权限、协议和样本，需在对应 TODO 解锁后补充真实记录。
